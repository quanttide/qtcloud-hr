# qtcloud_hr_studio 页面与组件规划

qtcloud_hr_studio 是量潮人事云工作台——侧边导航切换模块：总览、计划、招聘、培训、绩效、薪酬、关系。总览聚合各模块指标；计划管理方方面面计划；招聘做投递邮件初筛；培训管理培训人员的主线任务进度；绩效记录展示一个人在绩效周期里做了什么；薪酬按有效工时与职级时薪结算弹性薪资；关系管理入职、试用期、调动、晋升、降职、离职等员工生命周期。

## 页面规划

| 页面 | 路由 | 内容 |
|------|------|------|
| 总览仪表盘 | `/` | 各模块关键指标与最新动态聚合，一屏掌握全局。详细规划见 [screens/overview.md](./screens/overview.md) |
| 计划页面 | `/plans` | 计划管理：招聘计划、培训计划、绩效计划、薪酬计划等，状态与进度可追踪。详细规划见 [screens/plan.md](./screens/plan.md) |
| 招聘筛选 | `/recruitment` | 投递邮件初筛：正文/自荐检测，自动通过或拒绝，人工复核。已实现于 `lib/screens/recruitment_screen.dart` |
| 培训页面 | `/training` | 培训进度管理：主线任务进度（任务、起止时间、状态）与带教反馈，以真实业务为教材。详细规划见 [screens/training.md](./screens/training.md) |
| 绩效页面 | `/performance` | 绩效记录展示：一个人在一段绩效周期里做了什么——行为成果记录（时间、事项、结果），与前台结果对齐。详细规划见 [screens/performance.md](./screens/performance.md) |
| 薪酬页面 | `/compensation` | 有效工时结算：按有效工时记录计薪，时薪水平由职级决定，弹性薪资不做固定月薪。详细规划见 [screens/compensation.md](./screens/compensation.md) |
| 员工关系页面 | `/relations` | 员工生命周期记录：入职、试用期、调动、晋升、降职、离职，当前状态与事件可回溯。详细规划见 [screens/relation.md](./screens/relation.md) |

## 组件规划

招聘页面连接 `qtrecurit` CLI 能力的设计见 [qtrecurit-cli-integration.md](./qtrecurit-cli-integration.md)，实施计划见 [plan.md](./plan.md)，优先覆盖 `report` 和 `access` 命令。

- 指标卡：模块、数字、标签（总览）
- 动态条目：模块、标题、时间（总览）
- 计划条目：类型徽标、标题、周期、状态、进度
- 关系头部卡：员工、状态徽标、关键日期
- 生命周期事件条目：类型徽标、标题、时间、状态
- 状态说明卡：当前阶段、下一步
- 薪酬头部卡：员工、职级、薪酬周期、时薪
- 工时记录条目：日期、任务、有效工时
- 时薪对照卡：职级-时薪表（当前职级高亮）
- 结算结果卡：总工时、应发、调整、实发
- 培训头部卡：学员、阶段、带教人
- 任务进度条目：任务、起止时间、状态徽标
- 带教反馈卡：署名反馈、阶段小结
- 绩效头部卡：员工、身份、绩效周期
- 行为成果记录条目：时间、事项、结果
- 任务记录条目：任务、过程、结果
- 指标看板卡：数字资产贡献统计（参考指标）
- 评估结果卡：等级、署名评语、面谈

## 数据模型

- `record`：行为成果记录（时间、事项、结果）——绩效主体
- `cycle`：绩效/薪酬周期（周期、阶段状态）
- `metric`：参考指标（数字资产贡献统计，仅参考）
- `assessment`：评估（评估者、等级、评语）
- `compensation`：薪酬结算聚合（员工、职级、周期、时薪、工时明细、结算结果）
- `work_record`：有效工时记录（日期、任务、小时数）——薪酬主体
- `rate`：职级-时薪对照（职级等级 → 时薪水平）
- `settlement`：结算结果（总有效工时、应发、调整、实发）
- `training`：培训进度聚合（学员、阶段、带教人、任务链、反馈）
- `task`：主线任务（任务、起止时间、状态）——培训主体
- `feedback`：带教反馈（带教人、内容、阶段小结）
- `overview`：总览聚合（数据时点、指标列表、动态列表）
- `stat`：指标（模块、标签、数值）
- `activity`：动态（模块、标题、时间）
- `plan`：计划（类型、标题、周期、状态、进度）
- `employee_relation`：员工关系聚合（员工、当前状态、入职日、试用期、事件链）
- `relation_record`：生命周期事件（类型、标题、时间、状态）
- 事件类型：`onboard` / `probation` / `transfer` / `promotion` / `demotion` / `resignation`

字段以 `data/profile/` 为基准，mock 数据见 `assets/mock/`。
